# tennisnow

A personal tennis companion for hobby and club players. Log your sessions in
seconds, capture how you played **and** how you felt, and — over time — see what
brings out your best tennis.

This repo is governed by a small control system. **Read these before changing code:**

- [`CLAUDE.md`](CLAUDE.md) — architecture, coding, UX, design, performance and
  security rules, plus the do-not-break rules.
- [`memory.md.txt`](memory.md.txt) — durable decisions, pitfalls and insights.
- [`docs/decisions.md`](docs/decisions.md) — architecture decision records.

## Stack

Flutter + Dart · Riverpod (state) · go_router (navigation) · Drift/SQLite
(local-first, sync-ready persistence). See ADR-002/003 in `docs/decisions.md`.

## Getting started

This project depends on the Flutter SDK (`>=3.22`). The container used to author
it has no SDK, so generated files are not committed — generate them locally:

```bash
# 1. Create the platform folders (android/ ios/ etc.) into this existing project.
flutter create .

# 2. Fetch dependencies.
flutter pub get

# 3. Generate Drift code (creates lib/.../app_database.g.dart).
dart run build_runner build --delete-conflicting-outputs

# 4. Run.
flutter run

# Tests / static analysis
flutter test
flutter analyze
```

> Note: `*.g.dart` is git-ignored and regenerated by step 3.

## Architecture at a glance

```
lib/
  app/            # app shell + router
  core/           # constants, id generation, utils
  design_system/  # tokens + reusable widgets (the single visual source of truth)
  shared/domain/  # cross-feature value objects (e.g. Rating)
  features/
    session_logging/
      domain/         # entities, enums, repository interface (pure Dart)
      data/           # Drift database, mapper, repository implementation
      presentation/   # screens, widgets, Riverpod providers/controllers
```

Dependency rule: `presentation → domain ← data`. The domain layer is pure; the
UI talks to repository interfaces, never the database.

## Implemented so far

- **Log a session** — the core quick-log flow (type, optional result, duration,
  performance/mood/energy, equipment, notes) with smart defaults.
- **Session history** — live list with motivating empty, loading and error
  states, plus swipe-to-delete with undo (soft-delete).

Next up (not yet built): progress/trends, lightweight gamification, onboarding.
